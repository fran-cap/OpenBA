# CUSTOMMAPS hand-in

`ext.custom_maps`: a new game can start on a map file (`.bmap`) made in a map editor instead of a generated map. One class A toggle, **on by default** (maintainer ruling 2026-11-16; the New Game row is added only where the platform has a file dialog, `Platform::CanPickFile`), no serialized state, no lock; a pick is used by the next new game only.

**Status (2026-11-16): built, unit-tested, looked at in a game on Windows (DX11).** Based on `main` 34d87455. The file format, its checks, the origin byte of the coverage water and the other pure parts are covered by 53 unit tests (`tests/unit/ext_custom_maps_test.cpp`); the unit run (release flavour) is 2454 tests, 0 failures, 8 skipped, and the release exe builds with every seam below. The author started new games on map files in a Windows game: a caldera map and small islands (down to 1.5% of the play area above the water). The ground and the water looked as the editor drew them, and no dark band showed where two coverage tiles join. A map with no resource list got the game's own scatter, the town started exactly at the start cell of the island map and of the caldera map, with the selected start condition applied, and on the island map a merchant boat sailed all the way to the island although the map's water path runs along the bottom of the map, as in a generated game. A map with its own list of resources had them placed, and a save made on a custom map loaded with the extension turned off. On a map with no water path the log of the game had the "no boat route" line, and two such maps loaded in a row in one session logged it both times. The game runs above were made before the review of 2026-11-16; what changed in it (the New Game row as two table rows, the merchant guard's answer kept per world, the spawn-tile limits for a custom map only) was built and unit-tested. The New Game row as two table rows has been looked at in a game since (Windows, DX11): the label lines up with the Load custom map and Clear buttons and the map's name is on the row below. In the same build a custom map's own start cell worked as before, and the "no boat route" line appeared in the log of a map with no water path. Not looked at in a game since: merchants themselves on such a map, and the two limits on the spawn-tile spiral (they run only for a custom map with no start cell of its own and no disk that fits). Section 5 lists what was not done and not looked at.

## 1. What it does

A `.bmap` holds the height map, the water paths and, optionally, the placed resources and the town start (`src/ext/custom_maps/bmap.h` is the format). With the row on and a map picked in New Game:

1. **Terrain.** The terrain stage of world creation takes the file's height map and water paths in place of the generator's; everything after it (blend texture, meshes, water mesh, cell classification) runs unchanged (`world_seam.cpp`, called from `wg_HeightmapPipeline_f390`).
2. **Water.** The water mesh draws only inside the bounding box of a water feature, so a map file's underwater cells get coverage features (tiles of 200 cells, radius 98), with the seam fixes the island map uses (one z and a full AO weight for them, and the origin byte of section 3; `water_contour_mesh.cpp`).
3. **Size.** The game is built at the map's own size, a multiple of 8 from 64 to 1024, whatever sizes the chosen terrain lists (`BuildSize` in `WorldGeometry::BuildTerrain`, `LoadedSize` where the tile arrays are sized). The New Game dialog's Map size row is greyed while a map is picked.
4. **Resources.** A map that lists resources replaces the start-town scatter: each entry (template, play-area cell, model group, growth) is placed as the scatter places one (`StartTown_SpawnCustomResources` in `starttown.cpp`). An entry is skipped, with a count in the log, when its cell is outside the play area, taken, claimed by a building, under water or inside the town's clear disk (the start area's radius around the start spot, custom or default, which the game's own scatter also leaves clear), or its template does not resolve or is not a natural resource. The template's height and slope limits are not applied. A map with no list keeps the game's scatter.
5. **New Game row.** One row is added to the New Game dialog in use, vanilla or a mod's (MegaMod rebuilds the table and adds hint rows): `Dialog/NewGameMap.rsc` holds the row's elements only, and `new_game_map.cpp` builds them when the dialog opens and adds them as two more rows of the dialog's two-column table (`tableNew`, the same element in the game's dialog and in MegaMod's), so they line up with every other row whatever the column widths are: the first row has the label "Custom map" in the first column and the Load custom map and Clear buttons in the second, a label and its control on one row, as every other row has them; the second row has an empty first cell and, on the line below the buttons, the picked map's name and the mods line. A dialog with no such table gets the row at the end of the ribbon that holds the description box instead. The dialog's own resource, layout and width are untouched. The row is a **Load custom map** button, **Clear**, and the picked map's name and size. On Windows, when the maps folder (`Documents\Banished\Maps` when it exists, else `Documents\Banished`) holds `.bmap` files, the button opens the **Custom map picker** (`Dialog/CustomMapLoad.rsc`, `map_picker.cpp`): the game's Load screen for maps, a grid of thumbnails, each with the map's name, its author, its size as "512 x 512" with the file's date, and the mods it lists ("Needs: MegaMod"), newest first, with Load, Cancel and **Browse...**. The thumbnails are the files' PNGs (`png.cpp`, a small reader with its own DEFLATE decoder), scaled to the size of the Load screen's thumbnails and made into game images the way `ext.winter_ice` makes its textures. A file the loader refuses is listed dimmed with the Load screen's corrupt overlay and cannot be loaded. Browse, and the button when the folder is missing or empty, open the system file picker (`GetOpenFileNameW`); other platforms show "Not available on this platform yet". The file is parsed and checked (`Parse`, `Validate`) before it is used; a bad file is reported in the row and nothing changes.
6. **Mods.** A map can list the mods its resources came from (flag bit 2 of the file: for each mod its name, author and the templates the map uses from it). The list is information only; the game never refuses a map for it. When a map is picked, each listed mod is looked for by name (case does not matter) in the game's own mod list (`IO::Modification`, the list `SaveLoad::CheckMod` matches a save's mods against: each mod's display name and its enabled byte; `CheckModsInstalled` and `ModIsEnabled`, `mod_check.cpp`). No template is loaded from the menu: a lookup with the resource loader from there crashed the next loader pass in an earlier build. The row appends a short line naming the mods that are not enabled: `Needs: MegaMod`, or `Needs: A, B`, with at most two named and `and N more` after them (`ModsLine`). A mod is either enabled or not here; the partial `(3 of 40 missing)` form belongs to `CheckMods`, the lookup by template that the row no longer uses. The log has one line per mod. The check is written and unit tested; the line in the row has NOT been run in a game at this commit, and how long a line the text element shows is not known. When the game's mod list cannot be read, no mod is reported missing.
7. **Provenance.** A file can carry a provenance block (flag bit 3, 112 bytes): its content ID, an origin ID, a parent ID and two times. An ID is the SHA-256 of the map content only (heights, water paths, resources and start; not the name, author, note, thumbnail or mod list), so a copy that only changes those has the same ID; `bmap.h` writes down the exact bytes. The origin ID is the content ID of the first version and is kept by every save after it, the parent is the version a save was made from, and the times say when the origin and this version were saved. The map editor writes the block on every save and keeps the origin and parent when it opens a map and saves it again. The game uses none of it except one warning: when the stored content ID does not match the content, the issue list says another tool changed the file after it was saved. It proves nothing alone, because anyone can recompute or remove it; it is there so that a renamed copy is recognizable and an honest chain of edits stays readable.

With the row off none of this runs, with one exception: the merchant guard of section 3 (`MerchantRouteExists`), which stays on the trading post's path with the row off because a save made on a custom map loads with the row off. It answers from the world's boat polyline, read once per world (kept for the lock epoch, which a new game and a load both move), and is true on every generated map, so there it costs one compare of two integers per trading post tick and changes nothing.

## 2. Resource values

`variant` is the template's model group; 255 means the game chooses (a random group for a template that groups its models, the default model otherwise). `growth` is the growth progress times 250: 0 just planted, 250 fully grown; 255 means random, as the scatter gives. Trees run their first sub-resource step after registration, as the scatter does.

## 4. The editor

The map editor is a separate tool and is not part of this change: a single HTML page (no install) with brushes for the ground, water paths, the town start, and resources from the player's own game packages (a template with a `_naturalresource` part is a natural resource). It writes the `.bmap`, with the mod list. Its output was read back by `bmap.cpp`'s parser with no problems.

## 5. Not done

The gate and the resave check (the maintainer's; not run here); a run on the graphics backends other than the author's; the Load custom map button on platforms other than Windows (it shows "Not available on this platform yet": the map list opens only where the system file dialog exists, which is Windows so far, and the maps folder lookup, `BanishedDir`, is written for Windows paths); the template limits warning in the editor (they sit in the template's compiled `_naturalresource` file); another extension that chooses the New Game dialog's resource (`OpenNewGame`) would have to be reconciled with this one; none on `main` does.
