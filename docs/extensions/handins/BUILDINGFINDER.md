# BUILDINGFINDER hand-in (2026-11-03)

Branch `ext-building-finder`, on `main` 7ef6d00d. The task (the user's): "With big mods like MegaMod there are hundreds of toolbars to look through ... a search bar, so you can search for a building by name, or a favorites panel for buildings you mark ... it should be able to show all of the buildings, even the ones that you can't currently build." **Result: `ext.building_finder`, class A, off by default: a Find Buildings page in the extension window with a search box and the list of every building, and a small favorites window of the toolbar's own building buttons (opened by a button on the page, or by a hotkey, H until the player changes it).**

## 1. What a building is, and how it is placed
The toolbar is the `Toolbar` resources every loaded package brings (`Game/Toolbar.h`): each is an item with a parent group (`_field60`), an action (`_field48`: 0 opens a sub-toolbar, 1 "ShowGroup" selects a building tool, 2 opens a utility window, 4 focuses an entity), a template (`_field58`) and a shown flag (`_field45`). `ToolbarDialog::OnOpened` walks them with `ExternalFactory::FindNext` and keeps the ones of the group being opened. A building's button is an item with action 1; its text and sprite come from the template's `ToolbarDescription` (`_stringTable`/`_str3`, `_spriteSheet`/`_name`) and a press calls `PlayerToolManager::SelectTool(template)` (`ToolbarDialog::OnElementEvent`, case 1). The building's name is the description's title (`_str1`, what `BuildRequirementUI` and `ToolUI` show as `textTitle`); `_str3` is the toolbar button's tooltip text.

The page walks the same resources and keeps the shown items with action 1 and a template. A template that sits under more than one toolbar group is **one row**: the search finds it by the name of any of its groups, and the row lists them all in brackets (the text of the group's own toolbar item: what a mod put there, which is a real group name for some mods and a tooltip sentence for others). A press calls `SelectTool(template)` itself. It lists **all** of them: the toolbar greys a button when the town has as many of the template as its `ToolbarDescription` allows (`_val0`; negative = no limit; `ToolbarDialog::UpdateButtons`), and the page lists such a building too, with "(limit reached: n of m)" after its name, and says why nothing started when it is pressed. The count is the entities whose `_description` is the template, from the entity list's master array.

## 2. The page
`src/ext/ui/Dialog/BuildingFinderPage.rsc`: a hint, the search line (the game's edit field as the Family page's, a Clear button, "n buildings"), the list of all buildings, a status line, and a last row of two buttons ("Open Favorites Window" and "Favorites Window Hotkey: H"). A row is a small button (+ adds the building to the favorites, - takes it out; in a larger font) and a name button (the building's name and its groups in brackets, cut at 70 characters). The search wants every word typed in the name or in the names of the groups above it ("stone housing"); it is read every frame by the page's tick and rebuilds the list when the text changes, and the list scrolls back to its top when the search changes (a shorter result under an old scroll position showed nothing). The list shows the first 300 matches (the count says how many there are); a longer search narrows it. The status line says what the last press did; "Placing X." goes when the placing does (placed, cancelled, Esc): the page asks the tool manager whether the template is still its active tool group.

A press never changes a table from inside its own event: it is parked and the tick applies it (the Family page's way).

## 2a. The favorites window
`src/ext/ui/Dialog/FavoritesWindow.rsc`, `favorites_window.cpp`: a utility-style window like the family tree window (the game's own title bar, not modal, no pause, dragged by its title bar, it sits where the player left it during the session). The favorites are a grid of the toolbar's own building buttons: each is created from the toolbar's template for a building (`Dialog/Toolbar.rsc`, template 2, what `ToolbarDialog::OnOpened` clones for action 1) and given what `OnOpened` gives its button (the template as the user data, the description's text as the tip, the icon), so the size, the border and the tooltip dialog are the toolbar's (the tooltip shows the icon, title, description and cost). A button whose toolbar template cannot be loaded falls back to our own button with a plain two-line tooltip. A press starts placing the building and the window stays open, so another can be picked at once. A building at its limit is drawn dim (a disabled button shows no tooltip, so it is not disabled). Favorites are added and taken out on the page, not here. It is opened by the page's "Open Favorites Window" button and toggled by the hotkey; the grid follows the favorites file (a "+" on the page shows up here at once) and a limit that is reached or freed shows within about a second and a half.

The line under the grid is a short note (cut at 26 characters: it shares its line with a button, and a longer text would widen the window) and a button. With no favorites the button is "Open Find Buildings" (opens the extension window on the page: `Ext::Toolbar::ShowPage`); with some it is "Clear All", which asks again ("Sure? Clear All") and clears the list on the second press, or goes back after about five seconds.

The hotkey is read once per frame (`BuildingFinder::BeginFrame`, called from `GameUpdateLoop::Update` beside the other extensions') from the keyboard state the game itself polls: the game's index of the key is looked up in `Input::KeyTables::kIndexToVirtualKey`. It does nothing while a text box has the focus (the keyboard bindings are suspended then: `KeyMap::_suspendCount`), and nothing while a dialog that pauses the game is open (the pause menu: `UserInterface::PausesGame`); a key held through the menu's closing does not toggle the window afterwards. H is free in the game's default bindings (the camera, the tool and the toolbar keys are A W S D Q E R T, C V B X Z, F, the digits and F1-F9); a player who moved those keys may find it taken.

The page's "Favorites Window Hotkey" button changes the key: the next letter, digit or F1-F12 pressed becomes the hotkey (Esc gives up). A key the game already binds is refused with the binding's name (`KeyMap::GetIdForDeviceInput`, the name from the controls menu's `gameKeys` table), the same check the controls menu makes. The choice is `ext.building_finder_hotkey` in settings.cfg (the Win32 virtual key code; `Persistence::Set`, then `Ext::PersistSettings`), so it follows the player between towns. It is not a row of the game's controls menu: that list is fixed at the 50 retail bindings, and the dialog fills the rows its `.rsc` has.

## 3. The favorites
`building_favorites.txt` in the folder `settings.cfg` is in (`IO::SettingsStore::DefaultPath`), one template path per line (`#` lines and blanks skipped, at most 400). It is the player's, not the game's: it follows them from town to town and is in no save. A favorite whose mod is not loaded stays in the file and is left out of the grid (the note says how many).

## 4. Files and seams
| file | role |
|---|---|
| `src/ext/building_finder/finder_math.h` | the search, the favorites codec, the limit note, the hotkey names (pure, unit tested) |
| `src/ext/building_finder/building_finder.h` | the row's id, tab caption, page; the window and hotkey entry points |
| `src/ext/building_finder/finder_core.h/.cpp` | the walk, the favorites file, the hotkey setting, the built count (the toolbar's own), the rows and the icon grid (shared by the page and the window) |
| `src/ext/building_finder/toolbar_page.cpp` | the page: the list, the search, the presses |
| `src/ext/building_finder/favorites_window.cpp` | the favorites window and the hotkey |
| `src/ext/ui/Dialog/BuildingFinderPage.rsc` | the page; the texts are the `Finder*` and `Favorites*` keys of `ExtensionsStringTable.rsc` |
| `src/ext/ui/Dialog/FavoritesWindow.rsc` | the favorites window |
| `tools/ext_icons/buildingfinder.py` | the row's icon |
| `tests/unit/ext_building_finder_test.cpp` | the search, the favorites, the hotkey names |

The registration is the usual one: `registry.cpp/.h` (the row), `toolbar.h/.cpp` (the page; with ext.fps_counter the window has its 8 pages, the limit), `resources.cpp` and `CMakeLists.txt` (the two embedded `.rsc` files), `ExtensionsSprites.rsc` and the baked sprite data. The Extensions sprite sheet (512 x 1024 on main) takes this row's one new icon with room to spare (`docs/extensions/KITFREE.md` section 7). The one engine seam is a call in `GameUpdateLoop::Update` for the hotkey (an EXT SEAM comment beside the other extensions'). The other engine change moves no behavior: the toolbar's two inline counts of a template's entities in `ToolbarDialog::UpdateButtons` become one function, `Toolbar_BuiltCount` (`ToolbarDialog.h`), which the page and the window call too, so the "limit reached" test and the dimming use the same count as the toolbar's greying and no longer walk every entity.

Class A: the game keeps nothing and nothing in the simulation reads the row, so there is no state already in the town to deal with. It is off by default because it adds a tab. Rule 7: no game content; the page reads the loaded packages' toolbar resources at run time, and the row's icon is generated by `tools/ext_icons/buildingfinder.py`.

**Not looked at:** the exact rebased commit in a game (it is the same code on a newer `main`); the "already bound" refusal when a taken key is pressed for the hotkey; the dim icon of a building at its limit; the hotkey after a restart; a building whose toolbar item has no icon (a blank button with the toolbar's tooltip); Vulkan or Metal; Linux, Android or macOS (the unit tests build and run on Windows only here; the other platforms are CI's); the Windows gate and the resave check (the maintainer's).

## 6. Not done
* Hidden toolbar items (`_field45` false) are not listed: the toolbar does not show them either.
* The tutorial's building lock is not consulted; `SelectTool` applies it as the toolbar's button does.
* No keyboard shortcut for one favorite, the hotkey is not in the controls menu (see 2a), and the favorites window is not docked: it is dragged where the player wants it and is not remembered between sessions.
* A group's text is shown as the mod wrote it: some mods put a tooltip sentence where others put a group name.
