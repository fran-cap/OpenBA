# BETTERCAM hand-in (2026-10-18)

Branch `ext_better_camera`, based on `main` `2424a9093` (rebased onto `main` 01fbb55 for the PR; round 1 of the review changed the class to B and the toggle-off clamp, see section 3). The task (the user's idea): do for OpenBA what Banished Game Tweaks' camera fixes did for the retail exe,
as the simplest possible extension. **Result: `ext.better_camera`, one class B toggle (locked for the game, recorded in the save), off by default. Built, unit-tested and looked at in a running game (section 4).**

## 1. What it does
Retail's camera (`PlayerToolManager::UpdateCamera`, `src/game/Game/camera_input.cpp`) has two behaviours players ask to change:

| | retail | `ext.better_camera` on |
|---|---|---|
| zoom range (the zoom target `+0x3C`) | clamped to 20 .. 130 (`.rdata` 0x1401721c4 / 0x140172218) | 6 .. 200 (the top is the range the Game Tweaks exe fix has used since 2026-09, live-confirmed; the floor is 6, not that fix's 1: at the shallow tilt the eye is distance * sin 25 degrees above the focus point, 0.4 units at 1, and the camera clips the terrain (found in the PR review); at 6 it is about 2.5) |
| zoom normalisation (`normZ`, drives the pitch blend and the pan speed) | `(zoom - 20) / 110` (span at 0x14017220c) | `(zoom - 6) / 194`: the span is recomputed as max - min, as the exe fix does, so both keep their near-to-far shape across the wider range |
| pitch target | a blend of a NEAR slope pair (-25 / 60) and a weaker FAR pair (-65 / 85) by `normZ`: the view flattens toward top-down as you zoom out | the near pair at every zoom: the same tilt at every distance |

The pitch's own ceiling is deliberately NOT touched. `Vector3::FromYawPitch` is a fitted approximation that is only valid up to about 1.0 rad; the exe-fix research found that raising the
ceiling flips the camera to look at the sky (documented in the Game Tweaks notes, `CAMERA_PITCH_ZOOM_FINDINGS.md`).

## 3. Behaviour notes
* **Off is retail, bit for bit.** With the row off every value is retail's own constant and `PitchTarget(..., steady = false)` is retail's expression with the same terms in the same order
  (`ext_better_camera_off_is_retails_pitch_to_the_last_bit` compares exactly, over the manual pitch steps and a range of `normZ` that includes values outside 0..1).
* **Saves (class B).** With the row on, the zoom target (`+0x3C`) and the camera distance (`PlayerController::distance`, which follows it) are retail's own serialized fields but can hold values
  outside 20 .. 130, so the row is class B: locked for the game and recorded in the save as the pseudo-mod `ext:better_camera`; a retail game that loads such a save shows the standard missing-mod
  modal. The faithful route clamps the zoom target into 20 .. 130 **every frame the row is off** (`ClampToRetailRange`, after retail's own seeding of a zero target from the distance), not on a toggle edge:
  a save written with the row on, or a camera preset stored with it on (`ApplyCameraView` writes the stored distance straight back), hands the camera a target outside retail's range with no edge in
  between, and at 200 retail's `normZ` is (200 - 20) / 110 = 1.64 and the pitch blend extrapolates to about -101 degrees (retail's ceiling is -85), which flips the view. The clamp is a no-op for
  every value retail itself can hold (`ext_better_camera_clamp_to_retail_range_when_off` compares bit for bit; `ext_better_camera_a_wide_target_cannot_push_the_faithful_pitch_out_of_retails_range`
  shows the hazard and the clamp).
* **Diagnostics harness.** `camera_input.cpp`'s stress/camera sweep (`BANISHED_CAMERA_PIN`) still uses retail's constants; it is a test tool, not gameplay.
* **Draw distance / culling at zoom 200** was not examined here; the exe fix has used 200 in the retail game without problems.

## 6. Steady tilt moved to Camera angle (2026-11-08, maintainer ruling)

The row is now the zoom range only, shown as "Wider zoom" in the Extensions dialog and on the Enhanced tab. The steady tilt is `ext.camera_angle`'s slider at 90 (CAMERAANGLE.md); a settings.cfg with `ext.better_camera=1` and no `ext.camera_angle` key is migrated there at boot. `BetterCamera::PitchTarget` is still the pitch expression (called with `steady = false` and the far pair `CameraAngle::FarPair` hands it).

ON by default on a desktop since 1.0.3 (maintainer ruling 2026-11-08); the Android first run seeds `ext.better_camera=0`. Class B as before: a new game's save lists `ext:better_camera`.
