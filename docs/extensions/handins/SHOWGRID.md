# SHOWGRID hand-in (Show grid)

`ext.show_grid`: lines along the edges of the map's tiles, drawn over the ground while a game is on screen, so a player
who plans a town with the game paused can see where the tiles are. One class A row, **off by default**, live, no state
of its own (nothing is saved in the town).

## 1. What it does

With the row on, the game view shows a grid of thin white lines, one on every tile edge, lying on the terrain (they
follow hills) and hidden behind buildings, trees and anything else that stands in front of them. Every tenth line is
stronger and wider. Value keys (`src/ext/registry.cpp`) set the look; the Grid tab of the extension window (`ShowGridPage.rsc`, `toolbar_page.cpp`) has five sliders, one for each of these, and a check box that shows or hides the grid:

| Key | Range | Default | Meaning |
| --- | --- | --- | --- |
| `show_grid_opacity` | 10 to 100 | 75 | how solid the lines are (percent) |
| `show_grid_shade` | 0 to 100 | 100 | brightness: with no color 100 is white, 0 is black |
| `show_grid_hue` | 0 to 359 | 0 | the color's place on the wheel, in degrees (0 red, 120 green, 240 blue) |
| `show_grid_saturation` | 0 to 100 | 0 | 0 is white or grey, 100 the pure hue; the default keeps the grid white |
| `show_grid_width` | 1 to 30 | 6 | line width, in hundredths of a tile |

Only the part of the map in view is built: each frame nine rays (the screen's corners, edge middles and centre) are
marched across the terrain the way the game's mouse pick does, the cells they hit give a box (plus a margin of one
tile), and the triangles of that box's tile edges are built again only when the box, a value or the ground under the box changes (a hash of the heights under the box is read each frame, a few thousand vertices at most, so a loaded town or edited terrain gets its own lines). A view that
would need more than 10,000 tiles (`kMaxTiles`; zoomed out far) draws no grid: a grid that dense does not help.

**Why not the game's tile overlay.** The first version tinted whole tiles with the placement overlay's quads (the
material `Terrain/Selection.rsc`); a tinted ground read as a white haze. The grid is now line strips of triangles
(`show_grid_math.h`, pure and unit-tested), drawn with the same material and the same 0x18-byte vertex stream as the
overlay renderer (retail 0x1401008c0), because that material needs no new shader or resource. Its render state has the
depth test off (the placement tiles show through a building ghost), which put the lines over roofs; the grid draws with
a copy of that state, depth test on (less or equal), depth writes off (`GridState`), made once.

## 2. Why class A

It changes only what is drawn: no simulation state, no save data, nothing the game reads back. Off by default because
how the map looks is the player's choice (like `no_fog`).

## 2b. What it costs

Per frame, with the row on and the grid shown: nine ray marches across the terrain (the game's own pick march), one read of
each height under the box, and one draw call with the cached triangles (about 120,000 vertices for the largest box,
`kMaxTiles` 10,000). The triangles are made again only on a change, not every frame. With the row off, each seam is one
test of a flag. No game content ships: the icon is generated by `tools/ext_icons/showgrid.py`, the page is our own text
`.rsc`, and the line texture is a column of the game's own overlay atlas.

**Shown or hidden.** The check box is a runtime flag in `show_grid.cpp` (`Shown()` / `SetShown()`): it has no value key and
nothing is written to settings.cfg or a save. Every game starts with the grid hidden, whether or not the row was on when
the game began: `OnGameStart` clears the flag at every new game and load. Turning the row on in the Extensions dialog
shows the Grid tab; the grid appears once its box is ticked. The look settings (the five keys above) are kept. There is
no hotkey.

## 3. The seams

Three. Two draw seams, one line each behind `Ext::Ext().show_grid` and the check box, both before the tool draw (step 11),
so the tool's own tiles and a building ghost draw over the grid:

- `GameUpdateLoop::Draw` (`src/game/Game/gameupdateloop.cpp`), the normal path;
- `ext.render_pipe`'s draw (`src/ext/render_pipe/render_pipe.cpp`), the same place when that pipe runs the frame.

The third is in `GameUpdateLoop::Load` (`gameupdateloop_load.cpp`), after the class lock: `OnGameStart` (see section 1).

The icon is `tools/ext_icons/showgrid.py` (`Entry_show_grid.png`, `ExtensionsSprites.rsc`, rebaked
`ext_sprites_data.h`).

## 4. Not done yet

- No hotkey and nothing on the Enhanced tab: the Grid tab of the extension window holds the check box and the sliders.
  It is the first class A row with a tab there (a page may belong to a row of any class: DESIGN.md, surfaces).
- A steep slope can hide a line segment that lies inside the hill by less than the 0.03 tile lift.
- The grid is not in `ext.town_screenshot`'s pictures, nor in the game's own screenshot (the Take View Screenshot button):
  the town screenshot draws the scene at `GameUpdateLoop::Draw` step 7, and the game's screenshot is read back at step 9,
  both before the grid's step 11. Both were tried with the grid on. A change to those steps would show it.
- Performance was judged by eye in a game, not measured.

## 5. Tests

`tests/unit/ext_show_grid_test.cpp` (7): the box has a margin and stays in the map; no box without cells or when too big;
color (white, grey, the hues), width and bold lines; the hash of the heights under the box follows the ground; box
equality; the lines cover every tile edge once; the lines follow the ground. `ext_registry_values_test.cpp` pins the
value count (21), `ext_rsc_text_test.cpp` the page and its strings, `ext_toolbar_test.cpp` the page list and that every
page names an extension row, and `ext_registry_test.cpp` allows the row's description.

## 6. Verified

Looked at by the author in a game (Windows release build, 2026-10-31): lines on grass and over hills, hidden behind
houses, a barn and trees; the Grid tab with its check box and the opacity, hue, color, brightness and width sliders; a
new game starting with the grid hidden. A town screenshot and a view screenshot (the Take View Screenshot button) taken with the grid on show no grid. Not done: a hotkey, Linux, macOS and Android
builds here (CI builds them; the extension has no platform code, and the draw is the engine's own overlay path). The
Windows gate and the resave check are the maintainer's: the extension is class A and saves nothing.
