# TOWNSCREENSHOT hand-in (the Town Screenshot page)

`ext.town_screenshot`: one picture of the whole map from an isometric view, taken from a **Town Screenshot** page of the extension window while a game runs. One class B toggle, **off by default**, locked for the game, `formatVersion` 1, no state of its own (a screenshot is a file; nothing is saved in the town). Classed B only because the window's pages belong to B / C rows (section 2), not because the town plays differently.

## 1. What it does

With the row on, the extension window gets a **Town Screenshot** tab: three drop downs (**Quality**: Draft, Standard, High, Maximum, which are 4, 8, 12 and 16 pixels to the cell; **Angle**: Classic, 30 degrees down, the 2:1 look of pixel-art strategy games, or True isometric, 35.264 degrees, at which the three axes of a cube are drawn the same length; **Turn**: the diagonal view and each quarter turn, so the map can be seen from each of its four corners), two check boxes (**Ignore Weather**, on by default; **Hide Snow on the Ground**, off by default), the buttons **Take Town Screenshot** (a picture button: the game's own toolbar button with a camera glyph, `Glyph_town_screenshot_take`, its name the tool tip) **Take View Screenshot** (in a section of its own, **View Screenshot**, under the first, as the Terrain page keeps its resource tool apart from its brushes: a second picture button, a viewfinder glyph, `Glyph_town_screenshot_view`: a screenshot of what is on the screen now, see below) and **Cancel** (a small text button), and a line that says what is happening or how the last screenshot ended. A refusal ("Wait for the town screenshot to finish.") is shown for three seconds over the progress line, which the next tile would overwrite within a frame or two (the page asks every frame, `Contribution::tick`).

A screenshot is a file, `Screenshots\TownScreenshot<N>.png` in the save directory (the first N that does not exist), RGBA, with the corners outside the map transparent. It holds the whole map: terrain, water, trees and other resources, roads, buildings, citizens and animals, with no interface. A 512-cell map at Standard is about 5800 x 3500 pixels, at Maximum about 9400 x 6400 (a 640-cell map at Maximum is brought down to what fits in memory, below).

**How.** Isometric means a camera with no perspective: an orthographic one (`Volume::Frustum::isOrthographic`, the form the game already uses for the sun's shadow camera) looking down at the chosen angle. A screen is far smaller than the map, so the camera visits the picture a tile at a time. `screenshot_math.h` (pure, unit tested) does the arithmetic: the camera's axes (`MakeBasis`), the picture's extent (`ComputeFootprint`: the projection of the box the map and its ground heights fill), the tile grid (`MakeGrid`: each tile is a screen with a 64 pixel margin cut off every side, so a screen-space effect that lacks neighbours at the screen's edge, ambient occlusion above all, never reaches the picture; the middles are laid side by side) and where each tile's camera aims (`TileCentre`, `TileLookAt`). `town_screenshot.cpp` runs it: each frame draws the scene through the current tile's camera (`DrawScene`, the same `Renderer::Draw` the game makes, with the sun's shadow fit given the tile's camera through `SunLight::_extShadowFitView` as `ext.eye_camera` does), the first four frames of a tile are only drawn (the shadow map and the terrain's detail follow the camera), then the frame is read back (`FrameCopyImageBuffer`, as `GameUpdateLoop::TakeScreenshot` does) and its middle copied into the picture. At the end `PixelInsideMap` makes the pixels whose line of sight misses the map square transparent (the picture is the hexagon's bounding rectangle), SDL encodes the PNG in memory (`SDL_SavePNG_IO`) and the platform's file layer writes it, as the other extensions write files (`EnsureDirChain` for the folder, `FileCreateWrite` on a temporary name, `FileReplace` into place), so the path and the folder are the OS's own on every platform; then everything is put back.

**The view screenshot.** The second button saves the game's own screenshot of what is on the screen now: it raises the request the game's screenshot key raises (`GameUpdateLoop::m_quickSavePressed`), so `GameUpdateLoop::Draw` takes it after the scene and before the interface (`TakeScreenshot`, `Screenshots\Screenshot<N>.bmp`, the same file the key makes, without the interface or the extension window), with `ext.render_pipe` on or off. It is refused while a town screenshot is being taken.

**What it changes while it runs, and puts back** (on success, on Cancel, and when the game or the window changes under it):
- the game's pause (`PlayerToolManager::paused`): the game is paused so that citizens and animals stand still between tiles, and the pause is held: the pause key is locked for the run with retail's own lock (`GameUpdateLoop::m_gameFlags` bit 10, which `PlayerToolManager::UpdateHotkeys` tests; left alone if the game had it locked already), and `paused` is set again on every screenshot frame;
- `ext.render_pipe`, if it is on: it draws the frame on a render thread, one frame behind, through a path the tile camera does not reach, so it is switched off (`SetRequested`) for the screenshot and installed again (`SetRequested`, then `RenderPipe::Sync`) afterwards; the screenshot waits until the frame tail has removed it, and stops with a status line if 600 frames pass and it is still installed;
- the player's **status icons** option (`GameSettings::statusIconEnable`): the icons over buildings and citizens are scene items that `StatusIconGeometry::AddDrawItems` draws when it says so, and a screenshot leaves them out. The option is not changed for the run: `DrawOptions`, held by `GameUpdateLoop::Draw` for the length of one frame, reads it off while a screenshot is being taken and puts the player's value back when the frame ends, so the Options window, the save of the settings and the quit never see the change;
- with **Ignore Weather**, the player's **show weather** option (`GameSettings::showWeather`), the same way (`DrawOptions`, for the frame only): `WeatherSimulation::BlendLighting` mixes the rain and snow effects' lighting in only when it is on, and the particles are not drawn, so a rainy day is not grey;
- with **Hide Snow on the Ground**, the snow coverage the weather pushes to the terrain's shaders every frame (the first of the four floats `WeatherSimulation::DrawUpdate` copies into `Video::Context` +0x3B8 and the pixel constants) is zero for the screenshot's draws.
The player's own camera is never moved (the tile camera is a copy of it).

**Memory and time.** The picture is held whole, as 4 bytes a pixel, until it is written, so the pixels to the cell are lowered (by 5 percent steps, `ChoosePixelsPerCell`) until the picture holds at most 64 million pixels (256 MB); the status line says the size that came out. It is freed the moment the file is written. The log has one `[TownScreenshot] timings:` line per screenshot (the tiles, the corners, the PNG, in ms, and the picture's size). Encoding the PNG is the slowest part of a large screenshot and runs on the main thread: the game does not draw while it runs.

## 2. Why class B

Class A would be the honest class: a screenshot changes nothing about how a town plays and records nothing. But the extension window and its pages are built on B / C rows (the window is recorded and locked with the game: `docs/extensions/handins/EXTHOSTS.md`; the toolbar page test required B / C until `ext.show_grid`, 2026-11-01: `ext_toolbar_every_page_names_a_registered_extension`), and a page-less class A row would have no way for the player to take a screenshot. So the row is B (off by default, locked for the game, the faithful profile turns it off), with no state of its own. If the window should one day offer pages to class A rows, the row moves to A and nothing else changes.

## 3. The seams

One, in `GameUpdateLoop::Draw` step 7, before the `ext.eye_camera` branch: `if (Ext::Ext().town_screenshot && Ext::TownScreenshot::Active()) Ext::TownScreenshot::DrawScene(...)`. With the row off, or while no screenshot is being taken, the line is one test. No retail function is edited. `Toolbar::TownScreenshotPage()` is the page's contribution (`src/ext/town_screenshot/toolbar_page.cpp`, `src/ext/ui/Dialog/TownScreenshotPage.rsc`, the `TownScreenshot*` strings, the row's icon `Entry_town_screenshot.png` and the button's glyph, both from `tools/ext_icons/townscreenshot.py`).

## 4. Not done yet

- Ambient occlusion (`ext.ambient_occlusion`) is armed for the screenshot with the player's own zoom (its radius follows the camera's distance, and it fades with view depth); the tile camera stands far back, so the effect may be weaker in a screenshot than on screen. No artifact was seen in the screenshots taken with it on.
- The picture is the map as it is drawn: whatever is on screen as a 3D object is in it. The edges beyond the map are cut by the transparent corners, but a mountain outside the map that overlaps the map's outline in the view is kept.
- No progress bar or preview: the status line counts the tiles. A screenshot can be cancelled between tiles.
- No other formats than PNG; no sizes beyond the 64 million pixel cap; no choice of the tile's size.

## 5. Tests

`tests/unit/ext_town_screenshot_test.cpp`: the registry row (class B, off, `ext.town_screenshot`); the choices (quality, angle, turn); the basis is orthonormal and looks down for every angle and turn; the footprint of a flat map and of one with height; the pixels to the cell are capped by the picture's size, by the smallest step, and never below 1; the tile grid covers the picture without gaps (and a screen smaller than the margins still makes progress); the tile centre round trips through the camera's axes and puts each tile's middle on its part of the picture; the mask leaves the corners out and keeps the diamond of a flat map (half its rectangle), more with height, and everything when looking straight down. `tests/unit/ext_rsc_text_test.cpp` parses `TownScreenshotPage.rsc` (the three drop downs, both check boxes, both buttons, the status line, no unknown types); `tests/unit/ext_toolbar_test.cpp` counts the page. The camera, the read back, the PNG and the page need the running game.

## 6. Verified

Built and tested on Windows (MinGW) on `main` 39152f9 plus this branch: unit 1532 / 0 failures / 8 skipped (the kit skips); `tools/abi_audit.py` and `tools/acceptance/acceptance.sh` see the checks listed in the PR; `OpenBA.exe` builds. `resave_gate.sh Gate` was not run by the author (it launches the game; the Gate.sav fixture is not on the machine; a screenshot is not part of the save).

Looked at in a running game by the author (Windows, with `ext.render_pipe`, `ext.ambient_occlusion`, `ext.better_trees` and `ext.max_shadow_res` on): screenshots of a 512-cell map with a large modded town at 8, 12 and 13 pixels to the cell (Standard, High and Maximum, the last lowered by the cap), each a complete picture with the terrain, water, trees, buildings, citizens and animals, no seam at any tile join (checked at full size at joins in the forest, the river and the mountains), the corners transparent, the colors right; the status icons gone; on a rainy day and a snowy day with the options as chosen (Ignore Weather: clear lighting, no rain or snowfall; Hide Snow on the Ground: a bare ground; both off: the weather as it was); with and without `ext.no_fog` (no haze in either); a screenshot of the same game again, and a save loaded after several screenshots (the load of a large modded save was slow, about 48 seconds against 29 for the first load of the session, and the game was closed by the player just as it finished; the log shows no stall, and the timings line was added to make a screenshot's own cost visible). The four turns of the same 512-cell map (each a complete picture, rotated a quarter turn from the last) and both angles of a 256-cell map (35.264 degrees is taller than 30, as the arithmetic says: 2226 against 2035 pixels at 8 to the cell). The log's timings, a 512-cell map at 8 to the cell: 16 tiles in 1.5 s, the corners 0.2 s, the PNG 2.5 s. A 640-cell map at Maximum: the 16 pixels to the cell came down to 11.2 by the 64 million pixel cap, 10114 x 5887, 42 tiles, a 227 MB picture, the tiles 4.9 s, the corners 0.4 s, the PNG 6.2 s; Cancel in the middle of a Maximum screenshot of the same map (nothing written, the pause, the pipelined renderer and the two options put back, and a second screenshot taken after it). Not looked at: the View Screenshot button; a window that changes size during a screenshot; the device-lost case. After the maintainer's review (PR #54) the options were moved from the whole run to the frame (`DrawOptions`), the pause key was locked for the run, and the wait for `ext.render_pipe` was given an end; the author ran a town screenshot with them in a game afterwards and saw nothing wrong.
