# KITFREE: the extension resources without the Modding ToolKit

Opened 2026-10-17. The extension UI resources (the Extensions dialog, the Enhanced tab, the
string table, the sprite sheet) and ext.sharp_ui's font variants are compiled today by the
kit's `Tools-x64.exe` (`tools/ext_resources.sh`) and deployed loose into the game directory.
This phase builds every one of them INSIDE `OpenBA.exe` at run time, so a release is the exe
alone and the kit is no longer a build prerequisite. `tools/ext_resources.sh` stays until the
last block closes, as the cross-check (section 5), then goes.

## 1. Rulings (the user, 2026-10-17)

- **Not game content.** Our `.rsc` text is ours; the base objects it derives from are read
  from the user's installed packages at run time (DESIGN.md §3 rule 7: transform at load,
  never ship). Our sources never restate a line of the kit's `resource/` files.
- **The typeface.** FrancophilSans (Manfred Klein, "Simple Terms of Use": free for private and
  commercial use, a donation to Doctors Without Borders asked when there is profit, no bundling
  in "compilation CDs, disks or products" without permission; the author died in 2018). The user
  reads the clause as aimed at font-pack compilations and rules: the TTF ships in the **release
  package only** (never in the git tree), with Klein's readme beside it and a credit plus the
  donation request in README.md's licence section. The exe rasterises the INSTALLED face (or
  the one beside the exe) at run time and **falls back to the retail glyphs** when the face is
  absent, as ext.sharp_ui does today (`retail(no font)` / `retail(face)`).
- **Never commit a compiled `.crs`**: it carries the game's base values and glyph tables.

## 2. The mechanism: resource providers

A compiled resource is only a serialized object graph whose load ends in
`ExternalFactory::Add` (src/engine/object/external_add.cpp). The seam is a **provider**: when
the factory's lookup misses on disk (loose file and every package), `Ext::Resources::Provide`
is asked for the path; a provider that owns the path builds the `Object::External` in memory,
sets its path and the factory registers it like any loaded object. A provided object lives for
the process (corrected 2026-10-21): `Provide` stamps it with a usage bit the provider reserves
and no loop ever cleans, through retail's `Add` and its reference visit, so everything it points
at is kept too. It used to carry only the bits of the loops that touched it, and a cache hit
re-stamps a bit only while a loader runs, so the boot menu's `ExtensionsStringTable` /
`ExtensionsSprites` were cleaned at an in-game reload while the Extensions dialog first opened in
that game (the game's bit) kept pointing at them: the dialog reopened after an in-game B / C
change read a freed sprite sheet (a crash) or a freed string table (blank headings).

```
src/ext/resources/Resources.h      the provider interface (THIS header is shared; three blocks build on it)
src/ext/resources/resources.cpp    the provider table, Provide(), the load-miss seam (block RSCTEXT wires it)
src/ext/resources/text_reader.*    our text .rsc reader (block RSCTEXT)
src/ext/resources/sheet_builder.*  RGBA atlas -> SpriteSheet + MaterialInstance + ImageBuffer (block RSCSPRITE)
src/ext/resources/font_raster*.*   the run-time glyph rasteriser + Font objects (block RSCFONT)
```

Engine bodies stay faithful. The one engine-side line is the load-miss call into
`Ext::Resources::Provide`, marked `// EXT SEAM` like registry_boot.cpp's.

## 3. Blocks

| Block | Owns | Delivers |
|---|---|---|
| **RSCTEXT** | `src/ext/resources/{resources.cpp,text_reader.*}`, the seam, the embedding of `src/ext/ui/Dialog/*.rsc` into the exe | `Dialog/Extensions.rsc` (every named object), `Dialog/EnhancedOptions.rsc`, `Dialog/ExtensionsStringTable.rsc` provided from the embedded text. The text reader is an `IO::ReaderWriter` (Serializer.h's slot table: every Serialize body calls it with a FIELD NAME) that answers only the fields the text names; derivation `T name : "File.rsc:base"` = FindOrLoad the base, construct a fresh T, fill it from the base (the binary reader over the base's bytes, or a visitor copy), then run its Serialize against the text reader. An inherited array is REPLACED by the derived one (EXTRSC.md §1). `ExternalPtr` fields are strings resolved the way `ExternalPtr<T>::Serialize` resolves them. |
| **RSCSPRITE** | `src/ext/resources/sheet_builder.*`, `tools/ext_sprites_bake.py` -> `src/ext/resources/ext_sprites_data.h` | A generic builder: N RGBA bitmaps -> packed sheet (`_padForFiltering`, the kit's form) -> `UI::SpriteSheet` + `Graphics::MaterialInstance` (UI material, `Material/UI/uiMaterial.rsc` by reference) + `Video::ImageBuffer`, registered under three paths. The PNGs of `src/ext/ui/Dialog/Sprite/Extensions/` baked to RGBA arrays in a generated header (regenerated by the script; no PNG decoder in the exe). Provides `Dialog/ExtensionsSprites.rsc` (+`Material`, `Texture`). |
| **RSCFONT** | `src/ext/resources/font_raster*.*`, the release-package font files, README credit | `Font/Sharp<Kit>_<px>.rsc` provided on demand: the four game fonts rasterised at the picked height from the installed face (Win32 GDI, the API the kit's VideoCompiler uses; `src/platform/win/` seam, a posix twin later with FreeType), glyph metrics into `UI::Font`'s tables (Font.h: `_charToGlyph`, `_glyphs` kerning/advances, `_lineHeight`, `_baseLine`, `_spaceWidth`, the sheet) through RSCSPRITE's builder. The face is looked up installed, then as `FrancophilSans.ttf` beside the exe (`AddFontResourceEx` private). Absent: provide nothing, sharp_ui's fallback stands. |

Order: RSCTEXT and RSCSPRITE in parallel from the shared header; RSCFONT starts with the
rasteriser and the Font tables (its own test harness dumps a sheet PNG) and takes the builder
when RSCSPRITE lands.

## 4. Rules for the blocks

- NOT RETAIL code lives under `src/ext/`; the one engine seam is one line (section 2).
- No `getenv`; no new `BANISHED_*` flags; the tweak overlay is debug-only.
- Build with `tools/build.sh build` (agents `--jobs 2`); `tools/build.sh unit` for the tests;
  a game run only under `tools/game_dir_lock.sh acquire <block> 900` / `release`, polled with
  `tools/boot_state.sh --wait 300`, logs in `C:/GOG Games/Banished/` (`standalone_error.log`
  carries `[ExtDialog]` / `[SharpUI]`).
- Faithful profile untouched: a COMMAND-LINE `/profile:faithful` (`Ext::GateProfileForced`) never asks
  a provider at boot (no Extensions button, no sharp_ui), so the gate measures nothing new. A faithful
  profile chosen in settings.cfg keeps the providers (ruled 2026-10-18), so its Extensions button and
  the dialog's profile note work. One exception, on demand: opening a save
  that carries an `ext:` pseudo-mod registers the text provider (`Ext::Resources::InitText`, from
  `SaveLoadDialog::DoLoad`) so the entry's notice dialog exists under any profile
  (`docs/known_port_issues.md` row 1330). The gate's saves carry no `ext:` entry.

## 5. Cross-check (while the kit is still here)

For every provided object, the kit-compiled `.crs` is the oracle: write the provided object
with the ported `IO::BinaryWriter` to a memory stream and compare it to the kit's bytes
(`tools/ext_font_check.py` has the `.crs` block format and the LZF decoder). Dialog, tab and
string table must match byte for byte. The sprite sheet matches in everything but the packed
image (our packer may place sprites elsewhere; the sprite rectangles must still be consistent).
Font variants match in the tables' SHAPE (codepoints, glyph count, line height, baseline) and
are judged by eye in-game; the metrics differ from GDI-in-the-kit only by the rasteriser's
rounding.

## 6. Close-out

CLOSED 2026-10-18. With every kit-compiled loose file moved out of the game directory the menu
showed the Extensions button and its icon, the dialog opened (21 rows, every icon), the Enhanced
tab was added, and ext.sharp_ui at 83 % drew the four variants built in the exe
(`[SharpUI] ... fonts: Font->29 FontSmall->17 FontMedium->22 FontLarge->58`, each first build
6-9 ms). The deploy step no longer calls `tools/ext_resources.sh`; the script stays as the
cross-check oracle only (the unit tests skip their kit comparisons when its output is absent),
so `ToolKit/` stays git-ignored. README's "ToolKit needed once" line is gone; the typeface credit
is in README's Legal section. One fix on the way: ext.sharp_ui tested the disk for a variant
before loading it (`LooseCompiledExists`), so the provider was never asked; it now also accepts
`Ext::Resources::HasProvider`. Hand-ins: RSCTEXT.md, RSCSPRITE.md, RSCFONT.md.

## 7. The Extensions sprite sheet is 512 x 1024 (since 2026-11-04)

512 x 512 held 115 sprites and refused the 116th, so the height was doubled. Before that, 256 x 256 held 28 sprites: the 48 x 48 entry icons take 50 x 50 with the pad ring, and the 29th
failed `ext_sheet_pack_fits_pads_and_records`. The size is named once, by `_imageWidth` /
`_imageHeight` in `src/ext/ui/Dialog/ExtensionsSprites.rsc`. `tools/ext_sprites_bake.py` copies it
into `ext_sprites_data.h` (`kSheetWidth` / `kSheetHeight`), and the provider and the unit test read it
from there; the test pins 512 x 1024 so a silent change is caught. The kit compiles the same sheet,
so the cross-check needs no new expectation. On screen nothing moves: a row icon's size comes from
`Mod.rsc:imageIcon`, and the uvs are pixel edges over the sheet size. The 512 x 512 sheet had room for
about 90 entry icons; this one has about twice that. `ext.sharp_ui`'s 2x twins match sprites by name, not by position or sheet size,
and none is provided for this sheet.

**Adding an entry icon:**
1. Add `draw_<id>(px)` and an `ICONS` row (`"<id>": (tier, draw)`) to a module under
   `tools/ext_icons/`. The tier key picks the tile colour: `fix`, `A`, `B` or `C`.
2. Run `python tools/ext_sprites.py`. It rewrites every PNG under `src/ext/ui/Dialog/Sprite/Extensions/`.
   Only the new `Entry_<id>.png` should show in `git status`.
3. Add `{ String _name = "ExtensionsEntry_<id>"; String _source = "Sprite/Extensions/Entry_<id>.png"; }`
   to `ExtensionsSprites.rsc`. The dialog finds the sprite by that name (`EntrySprite` in
   `extensionsdialog.cpp`); no other wiring exists.
4. Run `python tools/ext_sprites_bake.py` and commit the header with the PNG and the `.rsc`.
5. Run `tools/ext_resources.sh`, then `tools/build.sh unit`: the pack test and `ext_sheet_kit_crosscheck`
   must pass. If the pack test fails, the sheet is full: double `_imageWidth` / `_imageHeight` and
   update the pinned value in the test.
