## Build plumbing

`BANISHED_SANITIZE=none|check|asan|ubsan|tsan|fuzz` (CMakeLists.txt) on top of any flavour;
`tools/build.sh` keys `build/cmake-<flavour>[-<backend>]-<sanitize>` from the env variable.
Under `asan` / `fuzz` the engine heap's instrument seat routes MemAlloc / MemFree to
`posix_memalign` / `free` (`src/engine/system/allocator.cpp`), so ASan sees every engine
allocation. UBSan runs without `vptr` and `alignment` (the type headers reinterpret memory).

`BANISHED_THREAD_SAFETY=ON` (clang only, any flavour) adds `-Wthread-safety
-Werror=thread-safety-analysis` to OpenBA and unit; the annotations are empty macros elsewhere
(`src/engine/system/thread_annotations.h`). The Linux check:
`CMAKE_EXTRA_MORE=-DBANISHED_THREAD_SAFETY=ON ~/lx_san.sh check build` on a fresh build directory.
Checked by the Linux (Vulkan) build only: the DX11 and Metal backends carry the annotations
unchecked, and their device-lock hand-offs (`contextdata.cpp`, `backend.mm`) are not yet marked.
What the analysis cannot follow is marked `NO_THREAD_SAFETY_ANALYSIS` with the reason beside it:
the device lock held from BeginCommands to PresentFrame (and moved across threads by
ext.render_pipe), retail's conditional Stream-lock exits (`Stream::Run`, `FreeChannelPlatform`),
a `Sys::MutexLock` dropped and re-taken through a reference (`RunClaimed`, `Complete`), the
derived cache's Open phase, and the pathfinder's ctor stores.

### S-001: resolved, retail behaviour (F-325)

The DX11 debug layer's id 351 (VS constant buffer slot 3 bound at 64 B where the shader declares
3328 B) is what retail does. In `VideoDX11-x64.dll`: ConstantBufferData::Create `0x180001300` builds
a banked buffer ladder with `ByteWidth = [R8+0x20]*(i+1)` (`IMUL ECX,ESI`); Bind `0x180001460` picks
the rung `[rsp+0x70] / [R11+0x20] - 1` and calls VSSetConstantBuffers only when the rung changes, then
UpdateSubresource; BindTransforms `0x180001c40` sizes the upload as `[ctx+0x20] SHL 6` from
`ctx+0x10d8` into the buffer at `ctx+0x2050`. The port's `buffers.cpp:851-876`, the Create ladder and
`contextdata.cpp:852` match instruction for instruction. The slot is `tc_` (`transform[52]`, 208
registers, 3328 B, bank stride 0x40); runs log rungs of 64 / 192 / 512 / 640 / 1216 B. On Vulkan,
`companions.cpp:651` copies only the rung bytes into the ring while the descriptor range is always
`kConstantBufferRange` (16384, `pipelines.h:96`, `draw.cpp:923`): a read past the rung is in range and
defined, and returns stale ring bytes where D3D11 returns zeros. Validation reports 0 errors. No fix.
